# rstar-advance 训练可靠性与消融验收改进方案

**已审阅的方案 · 2026-11-18 · 基于 `rstar-advance@b481c39`**。本次执行结果见[软件验收记录](../../reviews/2026-11-18-rstar-advance-training-acceptance.md)。

本次交付是修复 `train`、`pipeline`、`infer`、`evaluate` 的软件问题，接入 TensorBoard，实现逐轮保存与恢复，并用合成体模验证八组消融。用户尚未提供正式实验数据。方案经用户审阅后实施，软件验收通过后推送代码。设计依据见 [Spec v1.4 第 3–7 节](../specs/2026-11-18-rstar4d-cardiac-contour-ablation-design.md)。

## 1. 裁块支撑独立校验

- [ ] 在 `rstar4d/data/context.py` 独立计算当前架构需要的最小读取范围。逐轴考虑允许位移、LNCC 窗半径、参考梯度差分、插值邻点及 x2 特征编码的支撑，向外对齐全幅网格。以实际读入的 W 做比较。现有余量 [31,36,36] 是待回归验证的配方，最小需求由算子推导。
- [ ] 在数据加载、滑窗和配置解析处复用同一空间约定。容许真实扫描边缘截断；若漏读范围内有真实有效数据，在前向或损失计算前报告病例、轴、左右侧和缺少的 vox 数。主八组共享裁块范围，包括全关基准。
- [ ] 在 `tests/test_cardiac_primitives.py` 和 `tests/test_cardiac_training.py` 复现零余量案例。此前同一真值位移的 4096 个窗口整幅损失为 0、裁块为 0.0294358。验收覆盖不足支撑被拦截、合法扫描边缘通过、默认配方全幅与 W 的窗口数相同，FP32 数值满足 Spec 的容差。

## 2. 同病例多布局共用清单

- [ ] 在 `simulation/cardiac_layouts.py` 为 A/B 导出稳定且互异的样本标识 `sample_id`，保留 `case_id`、`animal_id`、布局、选中投影及共同参考哈希。旧清单缺少 `sample_id` 时使用 `case_id`。相同样本重复录入仍报错。提供生成含正确角度摘要的 A+B 联合清单的入口。
- [ ] 更新 `data/contracts.py`、`data/sampling.py`、推理输出、轮廓清单及配对报告。样本读取、验证块回放和输出路径使用样本标识；动物划分使用动物标识；跨布局配对使用原病例、相位、共同参考和明确的布局对照。训练按动物、原病例再选布局，固定每轮总抽样预算，避免添加布局就提高某只动物的权重。交换角度摘要继续仅用于诊断推理。
- [ ] 用同一体模的 A+B 同时完成一次训练、推理、评价。核对两份输出独立、能回配同一参考，同一模拟动物 ID 的全部记录都在同一 split。另测旧单布局清单、重复样本和角度来源不一致。

## 3. 全图评价的分母与逐相位报告

- [ ] 在 `evaluation/image_metrics.py` 和 `evaluation/report.py` 一次遍历中同时记录逐相位、整病例结果。每相位分别保留 MAE 有效体素数、SSIM 有效窗口数及缺失原因。沿用原有病例级汇总的权重。
- [ ] 在 `experiments/cardiac_ablation.py` 按共同动物、病例、布局及实际相位配对，按指标分别输出 `valid_states`、`valid_cases`、`valid_animals`。保留病例级对照，并单列逐相位配对结果。旧报告缺逐相位明细时保留已知病例数、标明相位数未知，可从已有预测重新评价。
- [ ] 用带有模拟动物与病例 ID 的两相位体模验证计数为 2 个相位、1 个病例、1 只动物。令一相位无完整 SSIM 窗，验证 MAE 仍有 2 个有效相位、SSIM 只有 1 个。覆盖组间缺相位及各相位有效体素数不等。

## 4. prior 错配诊断

- [ ] 在 `evaluation/prior_diagnostics.py` 记录逐例逐相位的筛选数，包括目标有效点、两条件各有一个粗候选、两侧均有有效细采样、有效细点数相同、值幅匹配和最终可比点。在 `models/prior_fusion.py` 的诊断回调中直接提供有效粗候选数。保持普通训练和推理的输出接口。
- [ ] 保留原体模作为零点对照，应重现 288 个目标位置、2 个符合单候选条件的位置、0 个正细采样配对。再构造具有连续插值支撑的体模，使粗搜索窗只遇到一个有效候选且其外侧仍有可读取的细采样邻域。固定目标、几何、有效域和模型，仅替换匹配或错配的 prior 内容。
- [ ] 正对照须有可比点，且能报告两侧门控均值、值特征幅度、修正量 RMS 和配对差。保留既定 10% 值幅容差。点的纳入不依赖修正量差的方向；真实验证集报告允许负、零或正差值。

## 5. Stage I 和 Stage II 每轮保存可恢复的 checkpoint

当前训练器会保存模型、Adam、学习率调度器、AMP scaler 和随机状态，每轮覆盖 `last.pt`，最优时更新 `best.pt`。恢复入口只接受所属 run 的 `last.pt`。若进程停在写完新 best、尚未写完 last 的时刻，两份文件可能指向不同轮次。

- [ ] 修改 `training/checkpoint.py`、`training/trainer.py`、`training/pipeline.py` 和 CLI。每个完成训练及验证的 epoch 原子发布一份完整归档，例如 `checkpoints/epoch-0003.pt`，所有轮次默认保留。归档记录阶段、完成轮次、下一轮、累计有效更新步数、全部训练状态、历史最优值及轮次、配置与数据签名、固定验证样本、随机状态和当轮指标。
- [ ] 以完整发布的轮次归档作为恢复依据。保留 `last.pt`、`best.pt` 供现有调用；按轮次归档修复中断留下的滞后别名和轮次汇总。临时文件及写入失败的归档不参与恢复。最新归档支持原目录续训；从较早归档继续时写入新 run，记录父 run 和起始轮次，继承当时的历史最优，保护原有训练历史。
- [ ] 明确恢复粒度。若第 8 轮中途退出，恢复第 7 轮完成时的状态，从第 8 轮首个样本重新开始。严格校验架构、数据、split 和训练签名。旧格式保留原有读取及兼容性检查；跨代码版本遇到训练语义变化时提供明确的 warm start 提示。
- [ ] 在确定性 FP32 上比较连续训练与退出后由新进程恢复的最终权重、优化器、调度器、更新步数、采样顺序及历史最优。对 CUDA AMP 另验 scaler 和下一次更新。注入写归档中途、归档完成但别名或日志未更新等中断。覆盖两个阶段、旧入口、历史轮次另存续跑及训练已结束时再次调用 pipeline。

## 6. TensorBoard 的曲线、图像与恢复

- [ ] 通过 `torch.utils.tensorboard.SummaryWriter` 接入正常训练入口，在训练环境和项目依赖中声明 TensorBoard。当前训练环境可导入 PyTorch 2.3.1+cu118、TensorBoard 2.16.2。事件目录按实验组、Stage 和 run 区分，同名标签可叠加比较八组。保留现有 JSONL 和 CSV。
- [ ] 每轮显示训练总损失、重建 L1、验证病例等权及动物等权 L1、学习率、有效优化步数、AMP 溢出、耗时和峰值显存。Stage II 增加运动、平滑及边界损失的原值和加权贡献、有效运动窗口数、越界率、整心与 LV 分别命中的块数和体素数。损失均值按相应分母计算；监督缺失时显示有效计数 0，跳过无定义均值。
- [ ] 每轮用固定验证样本、相位、切片和窗宽显示稀疏输入、prior、预测、参考图及同尺度绝对误差图；有可信人工标注时叠加两条参考边界。复用验证前向结果，只记录选定切片。独立评价结束后，把 Surface Dice、HD95、ASSD、有效动物数写到单独的评价面板。测试集指标仅在正式评价时写入。
- [ ] 轮级图表统一以完成的 epoch 为横轴，累计 optimizer step 作为单独指标。让日志与已提交 checkpoint 对齐，恢复时处理孤立或缺失的轮次事件，避免重复曲线。固定可视化不消耗训练随机数。用事件读取器实际核对标签、图像、轮次及曲线连续性，再验证开启记录与相同固定种子的训练结果一致。

## 7. 软件验收与推送

- [ ] 运行全套 unittest，用合成体模完成八组短程训练、A+B 多布局训练与评价、进程中断恢复和 TensorBoard 事件读取。验收报告列出使用的体模、测试结果和软件版本。
- [ ] 检查代码 diff 和提交范围，提交代码、测试、配置及说明，推送到 `origin/rstar-advance` 并比对远端提交 SHA。训练 ckpt 和 TensorBoard 事件保留在本地实验输出目录。

正式八组动物训练、真实 prior 错配诊断和留出动物轮廓评价属于后续研究。待用户提供并指定正式数据集后，再根据该数据集的动物身份、标注覆盖和采集信息制定运行安排。

## 审阅时值得确认的成本

建议两个阶段采用轮边界恢复，每个完成轮次长期保留一个完整训练断点。以未来正式训练的 60 + 8 × 30 轮预算为例，按体模文件大小估计，共 **300 份轮次归档，约 7.08 GiB**。本次软件验收使用短程体模训练。最优与最新副本、日志、图像及机制对照另计。
